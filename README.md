# Joplin Clipper Plus

Readability(Mozilla) 기반의 "간소화된 기사" 캡처를 핵심으로 한 조플린용 웹 클리퍼 크롬 확장(Manifest V3)입니다.

**크롬 웹 스토어**: https://chromewebstore.google.com/detail/joplin-clipper-plus/fbieoidncnoalmenkkpbcbomppoenfoa

## 기능
- 📄 **Article** — Readability로 본문만 추출해 마크다운으로 저장 (광고/사이드바 제거)
- 🖼 **Full Page** — 스크립트를 제거한 전체 페이지 HTML 스냅샷 저장
- ✂️ **Selection** — 드래그로 선택한 영역만 마크다운으로 저장. 선택 전에 모드를 먼저 누르면 페이지 우상단에 저장/취소 툴바가 떠서, 그 상태로 드래그 → 💾 Save
- 🔖 **Bookmark** — 링크 + 설명만 가볍게 저장
- 노트북 선택, 태그 입력, 제목 수정 지원
- 본문에 박힌 유튜브 임베드 영상은 조플린이 자동 재생 임베드하는 형태로 변환해서 저장 (Article/Selection 모드)
- 사이트 자체 호스팅 동영상(mp4 등, 움짤 형식 포함)도 재생 가능한 `<video>` 태그로 저장 (Article/Selection 모드)

## 설치 방법

### 1. 조플린에서 Web Clipper 활성화
1. 조플린 데스크톱 앱 실행
2. **도구 → 옵션 → Web Clipper**
3. "Web Clipper 서비스 활성화" 켜기
4. 표시되는 **Authorization token**을 복사

### 2. 확장 프로그램 설치
- **크롬 웹 스토어에서 설치 (권장)**: [Joplin Clipper Plus](https://chromewebstore.google.com/detail/joplin-clipper-plus/fbieoidncnoalmenkkpbcbomppoenfoa) 페이지에서 "Chrome에 추가"
- **직접 빌드해서 설치 (개발용)**:
  1. Chrome/Edge 주소창에 `chrome://extensions` (Edge는 `edge://extensions`) 입력
  2. 우측 상단 "개발자 모드" 켜기
  3. "압축해제된 확장 프로그램을 로드합니다" 클릭
  4. 이 폴더(`joplin-clipper`)를 선택

### 3. 토큰 등록
1. 확장 아이콘 클릭 → 팝업 상단의 "settings" 클릭 (또는 확장 관리 화면에서 "세부정보 → 확장 프로그램 옵션")
2. 포트(기본 41184)와 1단계에서 복사한 토큰 입력 → **Save**
3. **Test connection**으로 연결 확인 (조플린 앱이 켜져 있어야 함)

## 사용법
1. 클리핑하고 싶은 페이지로 이동
2. 확장 아이콘 클릭
3. 캡처 모드 선택 (Article / Full Page / Selection / Bookmark)
4. 제목 수정, 노트북 선택, 태그 입력 (선택)
5. **Clip to Joplin** 클릭

## 알려진 제한사항
- 이미지는 클리핑 시점에 1차로 `fetch`(올바른 Referer 자동 포함, 여러 장이면 병렬로 동시에)로 받아 옵니다. 가로폭이 1600px를 넘으면 자동으로 축소하고 JPEG(85% 품질)로 재압축한 뒤 base64로 박아 넣습니다 — 원본이 클수록 클리핑이 느려지는데, 이 축소 덕분에 대부분 크게 빨라집니다. `fetch` 자체가 CORS로 막혀 실패하면, 2차로 그 이미지를 화면에 스크롤해 보이게 한 뒤 **탭 스크린샷을 찍어 해당 영역만 잘라내는 방식**으로 캡처합니다. 이미지가 화면 세로 길이보다 크면 탭을 일시적으로 축소(zoom out)해서 통째로 한 번에 담거나, 그래도 안 들어갈 만큼 세로로 아주 긴 이미지(스크롤 웹툰 등)는 여러 장으로 나눠서 캡처합니다. **이 2차 폴백은 [content.js](content.js)의 `SCREENSHOT_FALLBACK_HOSTS`에 등록된 사이트에서만 시도됩니다** — 다른 사이트에서 fetch가 실패하면 그냥 원본 URL만 남기고 넘어갑니다. 이 2차 폴백은 탭이 실제로 화면에 보이고 포커스된 상태여야 동작하고(클리핑 중 다른 창으로 전환하면 실패할 수 있음), 클리핑 한 번에 최대 20장까지만 적용됩니다(캡처 API 자체 호출 빈도 제한 때문). 두 방법 다 실패하면 원본 URL만 남습니다. 세로로 매우 긴 이미지는 여러 장으로 나눠 찍어서 순서대로 이어붙이는데, 각 조각은 `<br>`로만 구분해 원본 이미지가 있던 자리의 HTML 구조(굵게 표시 등 인라인 서식)를 그대로 보존합니다.
- 이미지가 3장 이상인 게시글은 지연 로딩(`data-original`/`data-src`/`data-lazy-src`)으로 전환되는 사이트가 있어, 해당 속성도 확인합니다. 화면 밖에 있던 이미지는 스크롤해서 실제로 로드될 때까지 최대 4초 대기 후 캡처합니다 — 네트워크가 느리면 그래도 빈 이미지가 캡처될 수 있습니다.
- 이미지 1장당(축소 후 기준) 6MB 이상이면(스크린샷 폴백 제외) 노트 용량 문제로 건너뜁니다(원본 URL만 남음).
- 로컬 파일(`file://`), 크롬 내부 페이지(`chrome://`)에는 스크립트를 주입할 수 없어 클리핑이 되지 않습니다.
- 조플린 데스크톱 앱이 실행 중이어야 합니다 (Web Clipper 서비스가 앱 내부에서 로컬 서버로 돌아가는 방식).
- Article 모드는 게시판형 사이트에서 종종 엉뚱한 블록(사이드바, 목록 표)을 본문으로 잘못 판단할 수 있습니다. 그럴 땐 [content.js](content.js)의 `SITE_CONTENT_SELECTORS`에 `호스트명: "CSS 셀렉터"`를 추가하면 해당 사이트는 Readability를 건너뛰고 그 셀렉터에 매치되는 요소를 모두(제목/작성자/본문이 서로 다른 요소로 나뉘어 있으면 쉼표로 나열, 예: `".post_title, .post_author, .post_view"`) 문서 순서대로 합쳐서 뽑아옵니다 (디시인사이드, 클리앙이 이 방식으로 처리됨). 그 컨테이너 안에 여전히 원치 않는 위젯(추천 버튼, 첨부파일 목록 등)이 딸려오면 같은 파일의 `SITE_CLEANUP_SELECTORS`에 `호스트명: ["CSS 셀렉터", ...]` 형태로 추가하면 그 하위 요소들만 추가로 제거됩니다.
- 네이버 블로그처럼 실제 본문이 동일 출처 iframe 안에서 로드되는 사이트는 `SITE_IFRAME_SELECTORS`에 `호스트명: "iframe CSS 셀렉터"`를 추가하면 그 iframe 문서를 대신 분석합니다(Article 모드만 적용, Full Page/Bookmark 모드는 아직 미적용). Full Page 모드는 iframe 내용을 flatten하지 못해 이런 사이트에서는 여전히 빈 스냅샷이 나올 수 있습니다.
- `SITE_CONTENT_SELECTORS`에 등록되지 않은 사이트는 Readability를 쓰는데, 이게 본문 일부만 가져오는 경우(나무위키 등 빌드마다 클래스명이 바뀌는 SPA에서 흔함) `jcpHeadingLCA`가 자동으로 h1~h4 제목들의 공통 부모를 대신 시도합니다 — Readability보다 1.5배 이상 크면서 전체 페이지의 70% 미만일 때만 교체되는 보수적인 조건이라, 대부분의 정상 사이트에는 영향 없습니다. 그래도 여전히 부족하면 그 사이트도 `SITE_CONTENT_SELECTORS`로 직접 지정해주세요.

## 변경 이력
- **0.37.1** — 설정 화면의 Joplin API 토큰이 그대로 보이던 것을 비밀번호처럼 가림(화면 공유나 스크린샷에 토큰이 찍힐 수 있었음). 옵시디언 버전(0.38.0)에서 같은 문제를 발견해 함께 고침. 조플린 전용 변경이라 옵시디언 버전은 그대로.
- **0.37.0** — 실제 사이트를 돌며 옵시디언 버전과 함께 점검하다 찾은 문제 수정(공유 코드라 두 확장 모두 적용). ① **Daum 뉴스(v.daum.net) 지원 추가**: Readability가 요약/음성 듣기/번역/글자 크기 도구 패널, 랭킹 목록, 사이트 하단 메뉴까지 통째로 가져오던 문제 — 제목(`h3.tit_view`), 기자·날짜(`.info_view`), 본문(`.article_view`)만 지정. ② **이미지가 원격 주소로 남던 문제**: 이미지 서버가 `Access-Control-Allow-Origin: *`로 응답하면 쿠키를 붙인 요청(`credentials: "include"`)은 브라우저 규칙상 무조건 실패하는데, 그러면 이미지를 못 받고 원래 주소만 남았음(Daum, 오늘의유머 이미지 서버에서 확인). 이제 쿠키 없이 한 번 더 받고, 그래도 안 되면 확장 백그라운드로 받음(스크린샷 폴백을 쓰는 사이트는 기존 그대로). 고화질 원본(`data-originalurl`)을 끝내 못 받으면 페이지에 보이는 일반 화질(`src`)이라도 받음. ③ **아카라이브 이미지 일부 누락**: 한 글의 이미지를 한꺼번에 요청하면 서버가 429(요청이 너무 많음)를 돌려줌 — 백그라운드에서 받을 때 429면 잠깐 기다렸다 최대 3번 다시 시도(웹툰 모드에도 적용). ④ **더쿠 글 끝에 광고 추천 검색어**("개인정보 보호", "연예 잡지 구독" 등)가 섞이던 문제: 본문 안의 구글 광고 칸(`ins.adsbygoogle`)을 모든 사이트에서 제거. ⑤ **디시 글쓴이 옆 12×11 닉네임 아이콘**이 이미지로 같이 저장되던 문제: 정리 목록에 `.writer_nikcon img` 추가. 실제 크롬에서 디시(PC/모바일), 클리앙, 뽐뿌, 오늘의유머, 휴먼유니브(Article/웹툰), SLR, 이토랜드, 인벤, 더쿠, 82쿡, 아카, 루리웹, 네이버 블로그, 나무위키, 위키백과, Daum의 사진 있는 글로 확인(옵시디언 버전으로 저장해서 확인, 추출 코드는 같음).
- **0.36.1** — 옵시디언용 포크([Obsidian Clipper Plus](https://github.com/iamtalker/obsidian-clipper-plus))와 코드를 같이 쓰기 위한 내부 정리. 기능 변화 없음. `background.js`에서 조플린과 무관한 부분(페이지 주입, 이미지 캡처 폴백 전부, 메시지 처리)을 공통 파일 `core.js`로 분리하고, `background.js`에는 조플린 API 저장 코드만 남김. 팝업/툴바의 "Joplin" 문구는 확장 이름을 보고 자동으로 정해지도록 바꿔서 두 버전이 같은 파일을 쓸 수 있게 함. 공통 파일(`content.js`, `core.js`, `toolbar.js`, `popup.js`, `lib/`)을 옵시디언 폴더로 복사하는 `scripts/sync-to-obsidian.sh` 추가 — 앞으로 버전업 때마다 두 레포에 같은 버전으로 함께 올림. 실제 크롬에서 분리 후에도 Selection 툴바 → 저장 흐름이 그대로 동작함을 확인.
- **0.36.0** — Selection 모드를 **"모드 먼저 → 선택 → 저장"** 순서로 쓸 수 있게 페이지 위 플로팅 툴바 추가(사용자 요청). 예전엔 팝업이 페이지를 클릭하는 순간 닫히는 크롬 제약 때문에 "먼저 드래그 → 아이콘 → Selection → Clip" 순서만 가능했음. 이제 팝업에서 ✂️ Selection을 눌렀을 때 페이지에 선택된 부분이 **없으면** 팝업이 닫히고 페이지 우상단에 툴바(💾 Save / ✕ Cancel, 선택 글자 수 표시)가 뜸 → 드래그로 선택 → Save. 팝업에서 고른 노트북·태그(그리고 직접 고친 경우 제목)가 그대로 적용됨. 이미 선택된 부분이 **있으면** 예전처럼 팝업의 Clip으로 바로 저장. 툴바는 Shadow DOM 안에 그려서 사이트 CSS 영향을 안 받고, 버튼 클릭이 선택을 지우지 않도록 처리. - **0.5.0** — 이미지 관련 2가지 버그 수정: (1) 게시글에 이미지가 여러 장(3장 이상)이면 지연 로딩(lazy-load)으로 전환되어 `src` 대신 `data-original`에 실제 주소가 들어있는데, 이를 확인 안 해서 화면 밖 이미지가 통째로 빠지던 문제 — `data-original`/`data-src`도 확인하도록 수정. (2) 세로로 긴 이미지(전신 사진 등)가 화면 한 번에 안 들어가 가운데 부분만 찍혀서 위/아래(얼굴 등)가 잘리던 문제 — 스크롤하며 여러 조각으로 나눠 찍은 뒤 이어붙이도록 수정.
- **0.4.0** — 이미지 CORS 완전 차단(fetch 자체가 "Failed to fetch"로 실패) 사이트 대응. `fetch` 실패 시 탭 스크린샷 API(`chrome.tabs.captureVisibleTab`)로 실제 페이지에 렌더링된 이미지 영역만 잘라내 캡처하는 2차 폴백 추가. 디시인사이드(`dcimg*.dcinside.co.kr`)에서 확인.
- **0.3.1** — Turndown이 `<script>`/`<style>` 태그 내용을 기본적으로 걸러내지 않아 디시 게시글 본문에 박혀있는 이미지 번호매기기/광고 로딩용 인라인 스크립트가 그대로 마크다운에 새어나오던 문제 수정. 변환 전 DOM에서 확실히 제거(`jcpStripNonContentTags`) + Turndown `remove()` 이중 방어.
- **0.3.0** — 사이트별 본문 셀렉터 오버라이드(`SITE_CONTENT_SELECTORS`) 추가. 디시인사이드(`gall.dcinside.com`)처럼 하단 게시글 목록이 실제 본문보다 텍스트가 훨씬 많아 Readability가 페이지 전체를 통째로 긁어오는 사이트에 대응 — `.view_content_wrap`을 직접 지정해서 본문만 정확히 추출.
- **0.2.0** — 이미지 인라인화(base64) 추가로 핫링크 방지 이미지(디시 등) 대응. 게시판 네비게이션/메타 찌꺼기 제거(`jcpStripBoardChrome`). 팝업에 버전 표시 추가.
